## 1. 任务复述（给用户确认的一句话）

一个双击即开的 Windows 常驻小窗口：桌面上出现一只**背景透明、无边框、永远置顶、不在任务栏出现**的罗小黑（猫形态），会呼吸、眨眼、甩尾巴，瞳孔以 60Hz 跟随鼠标，可拖着走，右键弹出只含「退出」的菜单。**不含**养成、多角色、语音、开机自启、跨平台、任何联网。

### M8 的三个已验证约束（本轮实测，不是推断）

1. **`node --test <目录>` 在 Node v24.21.0 上退出码 1**（本轮探针实测）——位置参数给**目录**不被当作搜索根。**必须用 glob 模式**：`node --test "src/**/*.test.ts"`（正 / 反斜杠均可，本轮两种都验过退出码 0）。
2. **测试文件的 import 必须带 `.ts` 扩展名**（无扩展名导入实测 `ERR_MODULE_NOT_FOUND` 退出码 1）；`tsconfig.json` 已有 `allowImportingTsExtensions: true` + `noEmit: true`，**无需改 tsconfig**。
3. **`@types/node` 当前不存在**（`node_modules/@types` 只有 `react` / `react-dom`）→ 在 `src/` 放一个 `.test.ts` 后 `tsc --noEmit` 实测报 `TS2591` 退出码 2。**这是 §10 Q3 的唯一内容**：加 1 个 devDependency 即可，或改用零依赖但测试代码无类型检查的写法。

> 已知风险（4-1 处理，不改本卡）：`@types/node` 与 `lib: ["DOM"]` 并存可能引发 `setTimeout` 签名冲突（`number` vs `Timeout`）。出现时用 `ReturnType<typeof setTimeout>` 收敛类型，**不**去改 `tsconfig` 的 types 白名单。

## 7. 动作 4 · UI 描述

### 两个被定死的实现选择（防 4-1 分叉）

1. **右键菜单用 Tauri 原生菜单**，不用 HTML 自绘。依据：窗口只有 260×300，HTML 菜单**无法超出窗口边界**，且「点击窗口外的桌面关闭菜单」这件事在 HTML 方案里无法可靠捕获（那部分桌面不归我们的 WebView 管）。原生菜单只多一条权限 `core:menu:default`——`node_modules/@tauri-apps/api/menu.d.ts` 的 `@remarks` 原文：「All commands used by this module are part of the `core:menu:default`」。
2. **角色由 SVG + CSS `@keyframes` 表达，不引 Canvas**。依据：2-1 §5 方案 C 否决理由（净增 250~350 行状态机 + 失去 devtools 里可逐节点核对的 DOM 结构）。

### 视觉取值

具体色值、字号、圆角、阴影由 **3-5 色彩与风格**卡落 `docs/DESIGN_TOKENS.md`；动效时长与缓动由 **3-6 动效与微交互**卡落 `docs/MOTION.md`。本卡只定**上面表里的结构与时序数字**（它们是 M4/M5 验收命令的判据来源）。
